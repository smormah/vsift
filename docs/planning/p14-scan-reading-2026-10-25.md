# P14 scan reading, 2026-10-25 (RQ-13, R-SEC03), for the release candidate 0.2.3-rc.1

Status: a dated record of what was read on 2026-10-25, the day after `0.2.3-rc.1` was published (publish run 40038576713, ended 2026-10-24 at 01:32:28 UTC), at the tag `v0.2.3-rc.1`'s
commit `09e40398894f` (also the head of `release/0.2.x`; `main` has moved on), for the candidate that the stable `0.2.3` will be cut from. It repeats the method of
[`p14-scan-reading-2026-10-18.md`](p14-scan-reading-2026-10-18.md) (for `0.2.2-rc.1` and the stable `0.2.2`) over the window since that reading, and does not repeat the method sections of the earlier
readings it lists. It reads only public sources, with the tools' own default clients. Nothing was dismissed, closed, patched or changed in any setting, the FFmpeg and whisper.cpp catalogue was not
touched, nobody upstream was contacted, nothing was posted or commented anywhere, no issue was opened and nothing was installed on a developer machine.

**Result: the reading names one new finding, and it is not in anything that ships: the Node.js versions pinned for the tests (22.23.3) and for the publish job (24.21.0) are older than the
security releases of 2026-10-20.** Everything else agrees with 2026-10-18: no advisory names a locked crate at its locked version, the cycle's dependency changes are clean, the hosted `cargo deny`
and the one by hand say `advisories ok` for both lockfiles, the maintainer's acceptances stand unchanged, and two FFmpeg records new to the window name code VSift's configuration does not enable or
a library that is not FFmpeg's. **RQ-13 is recorded `passed` for `0.2.3-rc.1`** because the item's pass rule (plan section 6) is no open high or critical finding on a supported path unless fixed,
mitigated, or accepted by the maintainer with a register entry, and the Node.js pins are in the build, test and publish tooling, not in the executable or the launcher a person installs (the launcher
runs on the person's own Node.js). **The maintainer accepts the reading at the gate and decides what to do with the pins** (below, "Triage record"); the reading is evidence for that decision, not the
decision.

## What it does not show, and what is weaker than it sounds

- **A reading of public records and public history, not a test of a binary.** Nothing ran FFmpeg or whisper.cpp on a crafted input.
- **The Node.js row is a version comparison.** The reading did not trace whether any of the seven records touches the way the jobs use Node.js (the publish job talks to the registry and to GitHub by host name over TLS; the permission model, snapshots and Brotli responses are not known to be used), so it does not say the jobs were exposed, only that the pins are behind. The severities are the records' own, before NVD's analysis.
- **The records are a sample, and the freshest are the least analysed.** The Node.js records, the three new FFmpeg-keyword records and `CVE-2025-52290` are "Awaiting Analysis" or "Deferred".
- **Two inferences are not tests:** that MPEG-TS is not reachable (it rests on VSift's allow-lists, as on 2026-10-02) and that `01a292c7e365` fixes CVE-2025-9951 (it rests on the commit's message and the report's file name).
- **Gaps carried over:** the worker image's packages are unscanned; the Windows and macOS executables' system libraries were not read; the Homebrew tools of the macOS journeys and the pinned Windows tools are outside this reading; the native tools are not in the SBOM or in `cargo deny`; whether the catalogue's FFmpeg links `libaribb24` is not read.
- **A status, not a review of every alert:** zero alerts in a store that has been empty throughout shows no alert was raised, not that the code is free of findings.
