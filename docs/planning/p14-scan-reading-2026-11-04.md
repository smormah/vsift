Status: a dated record of what was read on 2026-11-04, the day `0.2.4-rc.1` was published (publish run 41822398268, ended 2026-11-04 at 12:09:31 UTC), at the tag `v0.2.4-rc.1`'s

## What it does not show, and what is weaker than it sounds

- **A reading of public records and public history, not a test of a binary.** Nothing ran FFmpeg or whisper.cpp on a crafted input. The `P14 malicious media` run (RQ-10) is the nearest thing to a test of the three new cases, and it is not this reading.
- **Three reachability arguments are from source and tables, not observed:** that the L-227 codecs can be named only by a file the probe opens (L-227), that an ARIB caption stream can be declared in a Matroska file (candidate 1), and that MPEG-TS and the IMF demuxer are not reachable (they rest on VSift's allow-lists, as on 2026-10-02).
- **Whether the catalogue's build links `libaribb24` is inferred** from BtbN's script, not read from the build's configure line.
- **The freshest records are the least analysed:** the L-227 five, CVE-2026-120210, the `libaribb24` pair, CVE-2025-52290 and CVE-2026-6385 are "Awaiting Analysis" or "Deferred", with the CNA's own scores.
- **`absent` in the ancestry tool is not by itself a finding** (a hand-written fix without a cherry-pick trailer reads `absent`); each `absent` here was matched to a record's own classification of an earlier reading or to L-227.
- **Gaps carried over:** the worker image's packages are unscanned; the Windows and macOS executables' system libraries were not read; the Homebrew tools of the macOS journeys and the pinned Windows tools (the Windows FFmpeg pin was not re-read: it is not changed on this branch) are outside this reading; the native tools are not in the SBOM or in `cargo deny`.
- **A status, not a review of every alert:** zero alerts in a store that has been empty throughout shows no alert was raised, not that the code is free of findings.
