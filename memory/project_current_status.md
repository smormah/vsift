## In plain English

VSift is a Rust command-line tool that gives anyone, and their AI assistant, local,
source-grounded access to the evidence in a video. Under
[ADR 0016](../docs/decisions/0016-embeddable-engine-and-evidence-contract.md) it is also an
embeddable engine library (`vsift`) that the CLI, and later other hosts, use. Today it can:
- check and register its dependencies, show a read-only setup plan, report whether local speech
  recognition really works here (`setup check`), and on Ubuntu 24.04 x86-64 install the reviewed
  FFmpeg, whisper.cpp and model itself, then list, roll back, remove and repair them (the store
  survives kills and, on Ubuntu 24.04 with ext4, power loss). **Since `0.2.1` the first `setup check`
  after a restart waits 30 seconds, not 5, and no longer calls a slow-starting, healthy tool missing (#391, closed). `0.1.0`, `0.2.0`
  and the first two `0.2.1` candidates still do. What the fix leaves is L-161;**
- copy a video into a private, disposable session; import an SRT or WebVTT transcript with it,
  aligned by an offset; or transcribe the speech itself with whisper.cpp (`transcript
  retranscribe`), continue an interrupted transcription, and report, resume or cancel that work.
  **Since `0.2.1` a 30-second stretch whose answer cannot be used is a recorded gap (the run answers `partial` and names it, #353) and merging the
  overlapping pieces no longer drops whole sentences silently at a seam (#359): it keeps a piece at the price of repeats and lists the stretches where words could not be placed;
  up to about half a second can still be missing (L-155 to L-160). Both are shown on stand-in recordings and synthetic layouts, not on the recordings that found the defects, and the
  listener's check of the holes on those two recordings is still to do. `0.2.0` has both defects;**
- return timestamped transcript segments, search them, list the moments where the screen changed,
  and return exact frames, neighbours, bursts, crops and WAV clips; **since `0.2.1`: `--view brief` on `transcript get`, `search` and `candidates` (the same ids, times and text
  without what every item repeats, a fifth to two fifths of the size; the default answer is unchanged) and a `transcript get` that states its coverage and is `partial` over a part
  nobody transcribed, as `search` is;**
- manage the session's lifetime and retention, validate retained bundles, stop a long command
  cleanly on Ctrl-C or `SIGTERM`, and keep every folder it creates private;
- run as a worker under an external supervisor (`session init-workspace`, `job run`, `job batch`),
  each step at most once per operation id; check an agent's draft report (`handoff check`); refuse
  to claim strict worker isolation unless the Linux kernel attests it. **Since `0.2.2` a worker stopped while it recognises speech records the stopped request as `cancelled` and resumable, and on Windows each provider runs in a console of its own (#404, `28cf6f8`); on `0.2.1` the journeys' shutdown stage failed twice on hosted Windows, and on `0.2.2-rc.1` and `0.2.2` it passed (two passes, not a rate). What the fix leaves is L-167;**
- be installed without Rust: **`0.2.2` is npm's `latest` (2026-10-18), so `npm install --global vsift-cli` with no tag installs it**; `next` names `0.2.2-rc.1` (kept there by decision);
  `0.1.0`, `0.2.0`, `0.2.1` and the candidates stay published (`0.2.0-rc.1`, `0.2.0-rc.2`, `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3` and `0.2.2-rc.1` are deprecated; `0.2.2`, `0.2.1` and `0.2.0` are not). Archives on the GitHub release
  carry a Sigstore attestation and npm carries provenance. **The README front page was rebuilt on 2026-10-16** (#413): real `0.2.1` output (with `--view brief`, a crop and `handoff check`), the terminal demo regenerated, the ids in the hero and the timeline renewed and the roadmap redrawn (R0 done, the `0.2.x` line, R1 planned; L-121 stays open, because the next release makes it stale again).

## Architecture snapshot

`vsift-domain` (values, no I/O) <- `vsift-application` (use cases and ports) <- `vsift-infrastructure`
(OS, processes, storage, providers, parsers) <- `vsift` (engine) <- `vsift-cli` (parse, present, signals).
`vsift-contract` sits beside the engine and owns the wire types. The skill only calls the `vsift` binary;
the trial harness uses only `vsift` and `vsift-contract`; `tools/` (never shipped) qualifies; `npm/` is the launcher.
